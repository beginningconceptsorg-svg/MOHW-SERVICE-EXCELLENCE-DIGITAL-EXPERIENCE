# Beginning Concepts Central AI — private pilot

This is an independent Cloudflare Worker, NOT a replacement for the existing gia-ai Worker. It uses the native Workers AI binding with Llama 3.3 70B Instruct FP8 Fast. This pilot contains only a small dated public-source catalogue; no internal CSAT report, report text, raw conversation history or secrets. The live Ella configuration is unchanged and cloud-disabled. This package is reusable; the registry separates tenant sources and the server controls tenant membership. Model answers are generated, not certified factual answers. Source IDs are validated but this does not prove that every statement is entailed by a source.

## Deploy once from Cloudflare dashboard
1. Confirm Workers is on the Free plan, including Workers AI. Do not upgrade to Paid. Review shared account usage (legacy gia-ai also consumes the same account quota). No Cloudflare account changes were made by committing these files.
2. Compute (Workers & Pages) > Create application > connect GitHub. Choose this repository, branch main, new Worker name **bc-central-ai**. In build configuration set root directory **cloud/central-ai**. Leave build command blank or use npm test; deploy command **npx wrangler deploy**. This is a Worker, not a Pages static website. Do not attach the existing gia-ai worker. If the dashboard requests permissions to install its GitHub integration, grant access only to this repo as appropriate.
3. After deployment, Settings > Variables and Secrets: add secret **PILOT_KEY** (random password at least 32 characters; do not paste into chat or GitHub), plain text **FREE_PLAN_CONFIRMED=true** only after verifying free plan, and **AI_ENABLED=true**. Default missing values fail closed. Turnstile and public tenant flags remain unset for private testing. The dashboard URL /health should show pilot_enabled true.
4. Open the new Worker's workers.dev URL. It serves a private-key-gated test lab. Enter the key directly into that page, choose Ella, consent, and ask public MOHW questions. The page does not persist the key; avoid all personal information. Try a question about the division and then 'why was it created?' The model uses source IDs to carry topic context, not full chat history.
5. Monitor actual Workers AI dashboard usage and the new Worker's behaviour. A custom domain such as ai.beginningconcepts.org may be added under Domains & Routes after pilot verification. Do not point Ella at it yet.

## Budget and security
The server requires explicit free-plan confirmation and a separate enable flag, plus an access key for the private same-origin pilot. There is no automatic deployment or billing change in GitHub. A single SQLite Durable Object serializes reservation of 30 model requests per UTC day total, 20 per tenant, and 4 per minute total, including failed inference attempts; input length is bounded and output limited to 220 tokens. This is a request cap, NOT an exact account-wide Neuron cap. Cloudflare's free plan is the hard billing boundary; other Workers may use the shared free quota. The server fails closed when the quota store is unavailable, when the model fails or when output has invalid sources. No raw questions are deliberately persisted or logged by this code; provider/platform data-handling and retention still require review. Do not use the pilot for sensitive data; basic input filters cannot detect all identifiers. Never store a secret in frontend code.

Public browser endpoint is disabled by default; later enable only after tenant approval, production Turnstile secret and widget integration, server-verified hostname/action and client consent, origin restrictions and real abuse testing. GitHub Pages origins are shared across repositories, so an origin match alone is not a tenant security boundary. Restrict public tenants to distinct approved custom hostnames before activation. The existing Ella adapter is intentionally not compatible with the public production authentication yet. The private test lab is the only intended client for this version. Do not flip approval flags or change Ella config as a shortcut. The current report's public distribution and any remote inference of internal material require Ministry authorisation. Review Cloudflare data-processing terms, privacy notices, quotas, model license, and real inference quality before rollout. After approved onboarding, add authenticated chat transport, evidence routing and fallback to Ella; retain local report calculations. No client data transfers between tenants.

## Test
Run npm test or node test.mjs. The logic tests run without network, with mocked model/auth/quota calls. They do not test live Cloudflare bindings, real inference, Turnstile or browser compatibility. GitHub CI runs these tests automatically. Use the pilot before evaluating naturalness. A successful build does not establish a successful real inference.
